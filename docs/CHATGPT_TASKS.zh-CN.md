# ChatGPT 定时任务成果 · 安装与使用

Start 在工作首页展示已有 ChatGPT 定时任务的真实 AI 输出。开启后先读本机缓存，再在需要时后台补充；项目和最近区不等待 ChatGPT。它不修改 ChatGPT 的任务计划、启用状态或原会话。

## 开启与阅读

1. 在同一个浏览器 Profile 中正常登录 ChatGPT。
2. 打开 Start → 设置 → 工作空间 → ChatGPT 定时任务，开启“同步任务与结果”，允许明确列出的 ChatGPT 网站访问、脚本与定时唤醒权限。会话目录收录和任务同步是两个独立开关。
3. 首次连接需要从 ChatGPT 读取任务与结果。读到以后，下一次打开首页直接使用本机成果。默认展示最近有结果的任务，也可自行选择最多十项。
4. 点击首页摘录，浏览其他任务或打开完整正文及原始来源。普通输出不被称为“业务成功”。可明确标记重要成果、无新信息或执行遇到问题；新的失败或无新信息不会清空保留的重要成果。

首页组件维持 44px 高度；展开面板按窗口适配，桌面最大宽度 520px。任务名称、成果产生时间和摘要优先呈现，读取诊断按需展开。面板与正文阅读过程中，后台变化不会替换正在读的版本；面板的“有更新 · 查看”由用户决定何时应用。此提示只表示当前面板有待应用的变化，不是永久未读计数。

## 各个操作的区别

| 操作 | 结果 |
| --- | --- |
| 隐藏首页组件 | 不在首页显示，仍可继续后台更新。 |
| 关闭结果预览 | 减少首页摘录，保留任务入口和同步。 |
| 关闭同步 | 停止后续收录、失效正在进行的写入，保留已有本机成果。 |
| 仅访问 ChatGPT 时同步 | 关闭自动后台读取，正常访问任务页和执行结果时收录。 |
| 清除任务缓存 | 清除本机任务与正文，不关闭同步，也不删除 ChatGPT 内容；之后会重新收录。 |
| 在 ChatGPT 退出登录 | 确认退出后立即隐藏原账户私密内容，等待正常登录恢复。 |

生活首页会清除任务标题、摘要与详情的页面内容；在生活模式主动打开工作空间设置时，仍可管理任务设置。清除任务缓存与“清除全部 Start 本地数据”不同：后者也会清除原会话目录等本机资料。

## 何时更新

默认使用已有的原生页面读取路径：每轮创建至多一个未激活的临时 ChatGPT 页面，串行读取任务列表和选中的结果，完成后释放。无需保持 ChatGPT 标签页常开；浏览器必须运行、权限有效且 ChatGPT 正常登录。没有采用已验证返回 401 的 Service Worker 直接请求，也不提取 cookie、bearer token 或修改浏览器凭证。

- **正常有启用任务：** 一次成功后约 30 分钟再检查。
- **没有启用任务：** 约两小时检查一次。
- **来源提供下次计划时间：** 可把检查提前到计划后约两分钟，但两次健康检查至少相隔五分钟。计划时间只是更新提示，不能证明任务实际完成；输出晚于检查时仍可能等到下一轮。
- **打开首页：** 缓存立即显示；后台仅检查持久化到期时间，未到期不创建来源页。多个首页和重复刷新共享同一轮进行中的读取。
- **主动重新读取：** 健康状态可提前检查；正在读取时合并请求；故障冷却或暂停期间不会通过重复点击增加请求。
- **浏览器休眠或重启：** 恢复并核对持久化闹钟、失败冷却和未完成轮次；浏览器关闭或睡眠期间不能持续读取。

临时页面不会主动激活窗口或夺取焦点。用户主动切到该页面时，它变为用户的正常页面：当前原生响应可继续收录，扩展不再导航或关闭它。此路径仍然需要一个临时标签，不能保证在所有操作系统、浏览器标签栏和真实站点验证流程中绝对不可见。

## 失败与恢复

读取失败不删除已验证成果，不把失败或空正文写成新的成功。诊断区分别保留最近尝试、成功读取和失败时间；时间不会因一次本地查看而变成“刚更新”。

| 情况 | 行为 |
| --- | --- |
| 断网、一般网络错误、超时 | 按约 5、10、20、40、60 分钟逐步延迟；上限一小时。当前请求没有任何响应时最多等待 45 秒。 |
| 429 限流 | 立即结束本轮，前五次按约 30、60、120、240、360 分钟退避；累计约 13.5 小时后第六次仍失败则暂停自动检查。冷却与暂停持久化，重启或重复点击不会绕过。 |
| 明确的来源验证 | 给正常页面一次短暂自行恢复机会，不点击或绕过验证；失败后约 30 分钟、两小时再试，连续第三次失败后暂停自动重试。 |
| 403 或无法识别的数据结构 | 不猜测为登录失效，不将结构错误当成空成功；按约两小时、四小时退避，连续第三次失败后暂停自动重试。 |
| 401／已退出 | 立即暂停，给出正常打开 ChatGPT 的入口；确认相同或新的登录主体后恢复。 |
| 仅获取到部分任务列表 | 保留已有任务和成果，不据缺席记录删除；约 30 分钟后检查，也可主动重新读取。不能承诺尚未实现的自动翻页。 |

暂停后，正常访问对应 ChatGPT 来源并成功读取可解除；适配器版本更新也会重新评估来源。其他无关页面的成功不会掩盖仍然失败的任务正文。界面不会在暂停时显示虚假的预计自动重试时间。

“已重新读取，暂无新输出”表示实际读取到了来源响应、正文版本没有变化，不等于用户对业务价值的“无新信息”标记。原来的重要成果和产生时间继续保留。

**新鲜度没有绝对最长保证。** 浏览器正常运行且来源健康时，一般按上述间隔更新；浏览器关闭、任务迟到、长期离线、验证暂停或登录失效会延长滞后。过期或需要处理时保留缓存、显示真实时间与一个明确的来源入口，不假装已经获取最新结果。

## 数据与来源边界

- 继承 PR #7 的结果模型及原有 41 项测试。最近运行、最近可读输出、保留的重要成果和同步状态分别存储；本轮不重写原模型。
- 正文按纯文本展示。摘录不是另一次 AI 摘要；来源链接采用正文中明确存在的网址和经过验证的原会话入口。不能判断业务成功时不会声称成功。
- 区分来源计划时间、成果产生时间、本机读取时间；缺失的运行时间和状态保持未知，不推算为真实完成。
- 支持标准 `conversation_id` 输出。只有 Dot/Work `aeon_id` 的任务可保留元数据，正文尚未接入。
- 仅当三个原生分类的列表范围完整时才认定完整覆盖。后续页或游标未读时保留部分范围；缺席的任务不从缓存删除。完整新列表已确认缺席的旧任务会停止重复后台读取，历史成果仍保留。
- 范围是当前浏览器 Profile、已确认登录主体及来源直接提供的 team。确认退出或换账户后，原私密 DOM 立即失效；数据库的主体、轻量首页快照和同步控制状态在同一事务中更新，旧异步响应不能恢复原内容。
- 离线扩展无法提前知道另一个页面或服务器上尚未被观察到的账户变化。首次观察到新主体后才可完成隔离；这不是全账号所有 Workspace 或所有历史结果的完整同步保证。
- 正文与结果历史保存在独立 `vaiwl-start-chatgpt-tasks` IndexedDB；原 `vaiwl-start` 资料库版本和 stores 不变。首页只取不含正文的快照，后台轮询只取控制状态。历史正文仍保留，长期总存储量及整份历史写入成本并非无限恒定。

## 安装、验证与集成

候选包是解压后加载的扩展开发包，不是商店发布。已有正式安装保留原目录、扩展 ID 和数据；本轮不会重装用户原扩展或清理生产数据库。需要隔离验证时使用新的测试 Profile。

本轮 PR #10 基于仍未合并的 PR #9 顶栏改动，并继承正式 main 已合入的 #7／#8；不重复导入模型或取代原生读取路径。main 与 #9 的实际状态应在合入时再次检查。没有擅自合并、商店发布或部署。

验收严格区分三层：

1. **代码检查：** 类型、模型／状态／调度测试、构建和审计。
2. **隔离浏览器：** 当前 PR head 的真实 Chrome-for-Testing/Chromium 与 Microsoft Edge 扩展安装，使用本地 HTTPS 合成来源和独立 Profile。生产 JavaScript 不改，测试 manifest 预授予同样的可选权限；不认证系统首次授权弹窗。
3. **真实账户：** #8 曾验证真实 Chrome 原生后台读取与正常访问收录。它只证明继承路径曾经可行，不代替本轮候选的真实账户、真实验证页、用户操作系统和真实 Edge 账户验收。本轮可用证据以当前报告为准。

实际数据、测量方法和限制见 `docs/evidence/task-quality-20261105/`；具体运行 SHA、耗时、网络、截图和通过项以 CI 产物及候选包 `build.json`、`verification/` 为准。四主题沿用 R1–R6：项目／最近区逻辑、工作生活单按钮、项目右上角 `+`、书签和卡片布局保持原契约。没有真实账户标题、正文或凭证写入公开仓库。
