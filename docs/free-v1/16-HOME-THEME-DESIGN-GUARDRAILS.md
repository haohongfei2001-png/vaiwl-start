# VAIWL Start · 全主题首页设计强制规范（2026-11-04）

状态：**用户确认的长期设计约束 / DESIGN_GUARDRAILS**。范围：Chrome/Edge 新标签页首页、工作空间/生活模式切换、项目区、最近区、相关设置，以及现有 B、C 与未来任何主题。**本文件定义最终产品应达到的行为，不代表这些功能已实现。**

## 权威与边界

- 本文件对于**首页可见信息、控件、交互及卡片布局**优先于 `02-INTERACTION-DESIGN.md`、第 15 号响应式修订等旧视觉规格；尤其覆盖旧文档中“项目头多功能菜单”“项目自然高度且禁止补位”“最近直接展开全部日期”的冲突语句。
- 第 14 号合同的项目归属、时间证据、活动含义与安全投影，第 12 号生活/工作模式数据边界，以及权限、账号隔离、IndexedDB、历史迁移规则继续有效。**视觉设计不得以本规范为由猜测活动、伪造时间或更改数据语义。**
- 每一次 Pro/Codex/设计审查，在制作主题图、原型、CSS 或交互方案前先逐条核对本规范；方案与之冲突时必须明确指出并修正。可以创新组件形式，但不得擅自删除或修改下面的产品行为。

## R1 · 隐藏所有项目/窗口总量

首页、项目区、最近区、标题、副标题、卡片、标签、角标、工具提示、空态、设置及用户可见的导入反馈均**不显示项目数量、窗口/会话数量或“还剩 X 个”**，也不将数字以装饰性徽章/占位形式放回。系统内部仍可计算必要数量用于分页、响应式布局和数据完整性校验；技术日志中的计数不属于 UI。时间日期、设置的时长选项不属于“项目/窗口总量”，可以如实显示。展开按钮写“展开更多”而不是“再显示 12 个”。

## R2 · 时间范围只在设置中出现，首页保留前后导航

- 首页不常驻显示“过去 30 天”“某日至某日”等**时间区间/跨度标签**；不额外建立显示时间跨度的导航条。当前范围的**长度在设置中可调**并持久化，默认沿用既有 30 个本地日历日。其他可选长度由正式实现根据数据、边界测试与产品简洁性确定，不在设计稿中伪装为已提供。
- 工作区保留紧凑的上一段/下一段箭头，逐段移动到相邻的连续范围；首页无需先去设置即可翻阅。最新段不可再向未来翻；空段也能准确翻阅、不偷偷跳过。箭头用可访问的“更早时段／更新时段”名称，不向视觉界面补回区间标签。
- “今天”“昨天”和必要时实际某一日的日期**是最近分组标题**，不是时间区间导航标签，允许展示；切换范围不修改真实活动时间或归属。范围长度改变时只重算投影，保留当前位置的合理锚点，不修改底层活动或创建假数据。

## R3 · 工作/生活模式只有一个小型切换按钮

顶栏只放**一个**体积克制的模式切换控件；点击一次立即在工作空间与生活模式之间反向切换，绝不使用两颗并列的“工作／生活”按钮或一整排 segmented control。文字/图标需清楚表达当前状态及点击目标；悬停、键盘、触屏与读屏皆可辨认。保留现有模式持久化、资料隔离及失败恢复合同。不得为美观复制第二处切换入口。

## R4 · 项目卡右上角唯一操作为「＋」

每张项目卡的**右上角只有一颗加号按钮**，语义固定为“在**这个项目**中新建 ChatGPT 对话”。不得再出现三点菜单、打开、搜索、展开、排序或其他头部操作按钮；不可用 hover 才显现第二排按钮绕过规则。项目名称/会话行仍可使用符合语义的链接或点击区域，正文区域的合理“展开更多”不受“右上角唯一操作”约束。

“＋”必须绑定已验证的目标项目标识和可信的原生新建入口；不得错误退化为通用新对话、在未知项目下创建或假装已创建成功。入口不具备时采用明确禁用/解释，不虚构导航结果。

## R5 · 「最近」的首屏分组与展开

“最近”采用**置顶 → 今天 → 昨天**的内容优先顺序，布局形态可以是与项目网格协调的列、紧凑条或其他经过真实对照验证的结构，不强制两列，也不做宽大且空旷的假卡。

- **有内容才出现**对应分组；没有置顶则不留“置顶”空框，没有今天/昨天则不留空分组或提示。相同会话在最近区只显示一次，置顶者不在今天/昨天再次复制。
- 置顶来自用户**明确选择**，不得由最近打开、访问频次或模型猜测自动产生；它是首页本地呈现偏好，不更改 ChatGPT 原生 Project 归属、真实活动时间与记录身份。置顶入口在最近区顶部稳定可达，翻阅历史时不制造重复实体；首次没有置顶时不显示空的置顶区。
- 在当前可显示的时间范围中，若三个分组全部为空而该范围仍有其他日期窗口，**直接展示其中最近的真实日期及该日期的会话**（如“10 月 28 日”）；若连这样的会话也没有，仅显示简洁空态并保留时间导航，不跨范围借用或编造数据。
- 最近区末尾以**一个小箭头**展开/收起所选时间范围内其余真实活跃的日期分组与窗口。展开箭头与上文时间范围前后箭头用途不同，必须在视觉、可访问名称与键盘操作上可区分；无可展开内容时不画无效按钮。
- 分组中的“今天／昨天”仅对当前现实日期成立；浏览较早范围时不错误显示今天/昨天。对原本时间不足以确认具体日期的会话，继续执行第 14 号时间证据规则，不能为了填满最近区伪造日期。
- “最近”的数据资格继续服从正式项目/最近投影规则：仅添加置顶和展示分组，不悄悄把已有项目会话重新判为“无项目”。

## R6 · 设置中切换两种项目卡片布局

设置提供**「等高卡片」／「按内容自适应」**两种明确互斥且持久化的选项，跨所有主题生效（换主题不应悄悄重置）。默认优先“按内容自适应”，符合首页高密度、少空白的方向；最终尺寸/动效可按主题创新。

1. **等高卡片**：同一断点的项目卡具有一致外部宽、高与网格节奏；即便只含一个会话，也显示完整高度的卡片，不因为内容少而缩成窄条。内容超出时用可访问、不会使同排高度忽然变化的查看更多/内部滚动或详情交互，不能截断为不可访问。
2. **按内容自适应**：卡片高度依据实际可见会话内容增长；**第二排及后续卡片应向上补位**，避免整排被首排最高卡片强行撑开产生大片死区。允许精确控制的多列错位/瀑布式排布（特此覆盖第 15 号“禁止瀑布流”旧约束），但项目排序必须稳定、数据项不重复、不在用户操作期间突变；视觉阅读次序和键盘焦点次序必须一致且可预测。
3. 两种模式都沿用受控最小卡宽、多断点响应式布局、真实标题、展开逻辑、滚动锚和交互安全点。不能通过隐藏会话、重排项目真实排序、硬裁切或固定数据样本造出“整齐”。

## 验收门槛

后续每一次首页主题设计、现有主题 B/C 优化及新增主题，必须对照以下检查并记录实际结果（设计稿标注设计验证、实装标注代码/浏览器验证，不互相冒充）：

- [ ] **R1** 全界面、空态、设置、tooltip 无项目/窗口计数。
- [ ] **R2** 首页无跨度标签；设置中可调；前后箭头逐段正确；空段/首段边界正确。
- [ ] **R3** 只有一个小型双向模式按钮，点击即切换，状态可理解。
- [ ] **R4** 每张项目卡头右上角只有绑定该项目的新对话“＋”，无隐藏菜单。
- [ ] **R5** 置顶/今天/昨天正确条件出现，全部缺失时显示最近真实日期，更多箭头只展开当前范围其余内容，时间来源可信、无重复。
- [ ] **R6** 两种布局均可从设置切换，等高低数据卡不收缩，自适应下一排上移补位，键盘与视觉顺序一致。
- [ ] 在 4/3/2/1 列、窄窗口、200% 缩放、零项目、单会话、混合长短卡、跨日/跨段、空段、置顶与无置顶、工作/生活模式中验证；Chrome/Edge 的产品内容和浏览器原生 UI 分开表述。
- [ ] 继承原数据/账号/权限/浏览器跳转和升级回归，不修改用户真实数据、不凭合成截图声称实机通过。

**设计自由度保留：** 主题配色、字体层级、边框、密度、空间节奏、列与条的表现形态、箭头位置与必要动效可继续创新，但不得违背 R1–R6。若后续用户明确修改任一规则，先更新本文件，再修改设计稿和产品实现，不得只在聊天里口头覆盖。
