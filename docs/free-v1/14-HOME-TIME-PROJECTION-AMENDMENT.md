## 正式废止

1. 废止“只有证明实际更早的会话才能进入较早会话”。**更早是低优先级收纳位置**，项目中的旧成员和无时间成员均进入其中。
2. 废止“原生项目／本地已观察／本地候选／待确认／尚无可用日期”等首页标签与独立区域。不改变底层 UNKNOWN、NONE、PROJECT 或局部关系状态。
3. 废止首页常驻本地保存说明和书签区重复“显示设置”。只有首次使用引导和影响操作的临时错误可以占用首页。
4. 废止把认证阶段当作项目卡的视觉类型。关系证据充分的正式、本地和旧兼容项目均使用同一组件；身份键仍隔离，绝不按名称合并。

## 位置规则

| 对象 | 首页位置 |
|---|---|
| 至少一个成员可定位当前30日区间 | 当前区间的一张项目卡 |
| 最近可定位成员在历史区间 | 对应历史区间的一张项目卡，当前区间不重复 |
| 项目显示区间内有时间依据的成员 | 正常列表，默认5条，每次增加12条 |
| 项目中更旧或没有时间依据的成员 | 同项目内“更早”，不丢弃、不拆项目 |
| 全部成员没有时间依据的真实项目 | 当前页全局紧凑“更早”项目入口，展开后仍是一张完整卡 |
| 只有真实项目ID/名称、没有成员 | 同一全局“更早”入口；可搜索、可打开，不制造会话 |
| 没有可用项目关系但有可定位时间 | 所在区间的“最近”，UNKNOWN/NONE仅为内部状态 |
| 没有可用项目关系也没有时间 | 不进入首页正常列表；全历史搜索仍可找到并打开 |

全局“更早”入口仅在 `k=0` 出现一次，不在每个30日区间重复。空历史段照常显示，不跳段。项目名、成员标题和URL搜索覆盖选中资料库所有日期以及空项目，不混其他账号/Profile。冲突成员不强行归项目；有直接时间时进入“最近”，无时间时只搜索可达。

## 时间事实与推断

直接显示时间是同一记录合法 Start 主动打开、浏览历史与可用原生时间事实的较新值。来源分别保留：浏览不等于发送，打开不等于发送；发现、刷新、重载、整页观察和项目活跃均不是成员活动。ISO日历、未来时刻、主体边界全部校验。

`VerifiedDisplayTimeFact` 保存来源、明确时间语义、原始时刻、观察时刻、Profile/owner/boundary与撤销状态。`NativeTimeOrderEvidence` 保存按新到旧的稳定record keys、排序语义、完整性/无置顶/无手动排序声明、原生适配版本、文档/路由/源修订、观察和过期时刻。只保存元数据，不保存消息、预览、原始DOM、令牌或完整会话JSON。

`deriveDisplayTimes()` 是纯领域函数。有效顺序形成上下界，多列表可求交；边界、环、时间冲突、过期、撤销和排序后发生的较新原生活动会使不适用的证据失效。只有范围完全落入一个30日区间才获得区间归属。没有精确日期就不显示“今天／昨天”或虚构时间；范围不能定位区间时仅用于项目内相对排序。推断不写入 activity、OpenDay、发送事件、browserLastVisitAt 或真实时间事实。

**锚点必须与原生排序语义匹配。** 列表按原生活动/更新时间排列时，浏览历史或Start打开时间不能充当该排序锚点。B昨天被访问、但消息一年前，不能据此推出排在B前的A近期活跃。浏览/打开仍可独立决定B自己的展示位置。已知2天前的兼容原生锚可为上方A提供当前区间下界；35天前下界不足以断言A近期；历史双锚可确定历史区间，无需制造精确日期。

## 实际来源接线与能力边界

现有经过连接权限、采集开关、隔离内容脚本、当前document/route、主体token校验的原生Project观察通道增加可选时间元数据；没有新增绕过P1的监听或写库入口。

`explicit-native-time/1` 仅在已证明的原生成员面板读取**具有明确更新语义标签的 `time[datetime]`**。仅有时间字符串或普通DOM排列不构成证据。相对排序还要求可见列表明确声明最近活动降序、完整成员数与连续位置元数据，并拒绝置顶、拖动/手动、加载中和局部列表干扰。缺少这些能力时，项目关系继续采集，无日期成员进入“更早”。新适配器是能力检测，不声称当前所有ChatGPT真实页面均暴露这些属性。

后台生成身份边界、观察时间、document摘要及源修订。顺序存于既有settings store的 `timeOrder:` 前缀；同项目后续缺失排序能力时撤销旧顺序，但保留成员及已成立的直接时间事实。顺序最长24小时有效，后续观察可刷新。原生时间来源目前只接入明确标签的更新时间；类型支持消息时间不等于新增正文读取或发送采集。

## 首页与稳定性

白底布局、30天上下导航、生活/工作切换、原生书签保持。顶栏唯一设置，筛选为 **全部／项目／最近**。项目卡只呈现名称、图标、成员、显示更多、更早及必要操作；整卡不折叠。书签默认单行、真实favicon、更多收起和逐层文件夹导航不变。

后台新证据通过既有SafeRendering安全点更新。pointer、drag、IME与键盘选择期间不搬动元素；更新保持实体焦点、滚动锚和用户当前历史段。当前聚焦成员进入项目更早或分页外时保留其可见性。项目观察的瞬时缺失不删除成员、不撤销可靠关系。

## Chrome原生页脚

扩展HTML不绘制该深色底栏。Chrome从138起在扩展新标签页上添加浏览器原生页脚；无公开扩展API允许产品自动关闭。设置中给出官方一次性操作：**右键底栏→隐藏新标签页页脚**；或**自定义Chrome→页脚→关闭显示**。主题仍可从Chrome菜单→设置→外观访问。不得改Profile/flags、私有API或宣称CSS能隐藏浏览器UI。依据和验证范围见 [平台核查](../evidence/home-workspace-20261103/PLATFORM.md)。

## 数据兼容

数据库仍为version 1、12 stores；不更改旧主键、索引、墓碑和活动。旧记录没有新字段时直接兼容。时间事实是ConversationRecord可选字段，顺序是settings附加行；历史刷新显式保留这些字段。同一主体关系更新不迁移旧活动；不同主体相同会话ID创建隔离记录，不复制时间/标题/活动。清库只有原有显式功能，本轮不执行。

旧构建能读取同版本数据库；更旧构建后续写入可能不保留其不认识的新字段，因此回退不是无损降级承诺。首页投影与搜索不修改任何业务store。
