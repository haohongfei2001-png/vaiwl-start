## A · 产品理解

首页的对象是用户已存在的 ChatGPT 工作，而不是新建任务、填写进度或阅读自动摘要。长期定位靠项目；回到近期的无项目会话靠日期；跨时间定位靠搜索。关闭浏览器标签不等于工作消失。

项目、会话、浏览器标签、活动事实是不同对象。项目卡来自正式投影，不能按照相似标题重新合并。最近只呈现原投影已允许的无项目记录，不能为了填充而抽取项目成员。标题按原有可信来源保留；访问、打开和发送不互相冒充。置顶是明确的本地选择；日期与范围仍依赖真实时间证据。

产品控制范围包括扩展顶栏、原生书签树的呈现、项目/最近、搜索、设置和生活页。浏览器地址栏、原生标签栏、浏览器自身书签栏及全屏提示均不属于扩展页面，不能通过产品 CSS 重新设计。

书签沿用原生树及 `_favicon` 来源；定时任务沿用现有独立授权、读取、正文和缓存模型，只在工作模式显示已选择且真实可读的结果。生活模式保留时钟、网页搜索与书签，清除工作 DOM 和读取订阅；不只是更换背景色。

审查入口：`AGENTS.md`、第 00/12/14/16/17 号合同、`projection.ts`、`time-evidence.ts`、`recent-presentation.ts`、`newtab.ts`、`spatial-home.ts`、`project-layout.ts`、`home-preferences.ts`、主题与设置控制器、书签与任务组件。数据资格和存储边界完全继承。

## B · 三种信息组织探索与裁决

用用户明确给出的 Riftlet 工程、VAIWL Start、PAIA 官网设计、想法这类真实工作对象检验布局，不假定它们有任何未观察到的状态、进度或执行结果。

| 方向 | 第一眼与进入路径 | 稀疏场景 | 密集场景与主要代价 | 裁决 |
| --- | --- | --- | --- | --- |
| 项目优先的目录桌面 | 全宽项目格，每卡直接列会话；最近放较弱的边栏 | 项目少时自然，但一条最近会话占整条边栏，永久牺牲项目宽度 | 项目多时效率高；无项目工作在窄侧栏中长标题截断严重 | 保留项目稳定位置，取消固定侧栏 |
| 近期流优先 | 按真实日期浏览，项目作为上方紧凑入口 | 单条最近会话会成为一个过大的视觉中心 | 日常无项目会话占主导，长期工作必须多走一步；不能把项目成员塞入最近补足流 | 不采用；与长期工作组织价值不符 |
| 项目和最近共用浏览尺度 | 项目在上、日期索引在下，共用内容边界、列线和会话行；同一顶栏控制 | 无数据的组不画；单条近期会话具有受控阅读宽度，其余空间自然结束 | 多项目按既有顺序补位；最近逐日期、逐行横向阅读；同一单元不重复 | 采用 |

选择依据：视觉权重随内容角色变化，信息结构保持一致。项目是有边界的工作容器，最近是更轻的日期索引；不能把两者都做成等高大卡，也不能以毫无依据的模块填满页面。

稀疏时保留项目的固定列宽，单卡不扩成巨卡。最近只含一条时最多占两列，让长标题可读，仍不画空的右侧容器。其余会话按四列逐行排列，不使用 CSS columns 改变阅读次序。每个日期组独立；置顶、今天、昨天及日期回退完全由同一个领域函数决定。

## C · 共享设计系统

| 层级 | 决策 |
| --- | --- |
| 内容宽度 | 最大 1360 CSS px；桌面左右 48px；≤1180 为36px，≤850 为24px，≤600 为20px |
| 栅格 | 所有主题 >1180 四列；851–1180 三列；601–850 两列；≤600 一列；空列不拉伸 |
| 横向间距 | 24/20/18/16px，随对应断点调整 |
| 顶部 | 60px；单一模式按钮、内容筛选、相邻时段箭头、真实任务入口、短搜索、新对话、设置。常驻产品名退出；身份保留在设置 |
| 窄窗口 | ≤760px 两行命令；有资料库选择器时 ≤1050px 提前两行，不用压小文字来挤入 |
| 书签 | 独占一行、真实图标、原生顺序和文件夹；溢出仍用原测量/展开机制 |
| 字体 | 原系统字体；内容14px/22px，项目标题14px/21px/600，区域标题14px/22px/600，日期12px/20px，辅助操作11–12px |
| 项目 | 标题可两行；原四条真实预览和整行详情展开保留；单一加号保留可信入口边界 |
| 等高 | 256px；≤600 为280px；粗指针296px。预览不得被遮挡，更多内容由外部展开区域访问 |
| 自适应 | 沿用已验证的最短列测量布局，DOM 原顺序不变，按 y/x 阅读与键盘一致；展开区是全宽屏障 |
| 最近 | 轻日期标题，组内与项目同一列线；标题可两行，单条最多跨两列。没有固定面板高度 |
| 层次 | 全局命令低调但稳定；项目内容为主；最近轻量；辅助操作低对比但可辨认。没有数量徽章 |
| 状态 | 悬停轻底色、键盘可见焦点；不使用卡片上浮和布局动画；120ms边界色过渡，遵循减少动态效果偏好 |
| 空状态 | 首次使用仍给连接/导入入口；空历史段保留时间导航和搜索，不跨范围借内容 |

主题使用共用的 `--project-*`、`--symbol-*`、`--expanded-surface`、颜色、间距和列数 Token。经典保留细边界及层级线；空间使用柔和绿色中性表面；分区使用紫灰工具面、标题分区；书页使用开放的纸色底与书脊。四者均为同一信息架构，不再让主题决定项目列数或把最近搬到另一边。

设置中的主题预览同步更新，不继续展示已不存在的侧栏构图。主题键、布局键、时段长度和模式偏好不迁移、不重置。

历史时段或筛选生效时，时段箭头旁出现小型回首页动作，一击回到最新并显示全部工作，随后焦点回到“全部”。这是原经典主题品牌按钮的返回能力在共享顶栏中的保留，不是新的时段标签。

## D · 实现边界

正式修改首页渲染接线、共享呈现组件、四主题 CSS、共享布局、设置预览及相关验收。保留现有范围投影、标题可信度、账号边界、存储、后台采集、导航 broker、权限、书签树和任务来源逻辑。

“＋”当前依旧是明确 `aria-disabled` 的项目内创建入口占位：已验证项目主页不等于已验证项目新会话入口。本轮不把它改成通用新对话，也不把已有能力缺口伪装成已解决。

## 第一方设计研究及取舍

下列公开资料用于研究方法；功能与界面结构仍由本产品的真实能力和第16号规范决定。

| 产品及第一方来源 | 对本次设计有用的方法 | 本产品中的实际取舍 |
| --- | --- | --- |
| [Linear · UI refresh](https://linear.app/changelog/2026-03-12-ui-refresh) | 统一标题、导航和视图控制，降低导航的视觉强度 | 四主题共用命令位置与内容栅格，主要视觉留给项目 |
| [Linear · Display options](https://linear.app/docs/display-options) | 可预测的分组、排序和持久显示偏好 | 卡片高度、时段、主题各自保存，不让换主题改变数据 |
| [Craft · Organize](https://www.craft.do/organize) | 结构适应内容，按需要增加组织层次 | 单条最近不制造大容器，稀疏状态正常结束 |
| [Arc · Find deep focus](https://start.arc.net/find-focus) | 弱化干扰，保留工作上下文与返回路径 | 控制界面体积，项目和搜索承担回到工作的入口 |
| [mymind · How mymind works](https://mymind.helpscoutdocs.com/article/68-how-mymind-works) | 降低维护成本、自然浏览已有信息 | 不要求用户为首页重录工作，也不新增自动分类和摘要 |
| [Raycast · Search Bar](https://manual.raycast.com/search-bar) | 单一全局检索和明确动作 | 短入口打开完整搜索，不让大搜索框占据首屏 |
| [Notion · Navigate with the sidebar](https://www.notion.com/help/navigate-with-the-sidebar) | 层级和渐进披露 | 保留项目展开、更多日期和按需设置，不一次铺开所有内容 |
| [Claude · Chat search and memory](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context) | 重访旧会话及明确的项目边界 | 让已有工作可达，保留真实项目归属；不引入模型生成信息 |

独立研究赞成统一工作面，另建议1280使用三列、最近固定两列、最大宽度约1440。实施负责人进一步考虑本轮要求的项目与最近连续性、空间利用及稀疏状态，以1360最大宽度和四列轻索引作为起点。1280宽度下卡片为278px；长标题的可读性与稀疏变化需用截图继续裁决。单条最近跨两列只改变阅读宽度，内容左起点、实体、顺序与日期不变；新增记录仍经过原有交互安全更新。
